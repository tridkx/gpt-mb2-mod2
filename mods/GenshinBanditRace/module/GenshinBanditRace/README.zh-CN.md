# Genshin Bandit Race

骑砍2 v1.4.8 原神土匪混编独立 Mod，支持沙盒与故事战役，包括故事教程结束／跳过教程后的自然土匪生成。复用 **Genshin Race Collection v0.1.3** 的22个完整角色种族，新增22个 T3／Level 16 土匪兵种，使用原版对应 T5 的熟练度、武器、固有护甲及等效防具重量。模型资源保留在原神合集，不复制或修改合集。

## 混编规则

覆盖劫匪、海寇、山贼、森林强盗、草原强盗、沙漠强盗六类自然生成地图队伍。每类统一使用完整22兵种池，每次等概率抽取，允许同队重复；没有地域或文化差分，所有类别都可能出现近战骑兵和骑射兵。小队不保证同时出现全部22类。

| MCM设置 | 默认 | 范围 |
| --- | --- | --- |
| 启用新队伍混编 | 开 | 开／关 |
| 使用固定人数模式 | 关，即比例模式 | 开／关 |
| 原神兵比例 | 30% | 0～100% |
| 每队固定原神兵人数 | 5 | 0～500 |
| 等效防具负重倍率 | 1 | 0～2 |

比例模式按最终队伍总人数四舍五入，固定模式取指定人数；最多替换可用的原版土匪，不替换英雄、俘虏和其他来源兵员。先确定替换配额，再从原版各级兵员中按人数随机替换，总人数守恒。只处理新自然生成队伍，不重建旧队；逃兵、任务专用队、藏身处驻留／首领队和海上舰队不在范围内。

可以单独使用。与 Bandit Population Tuning 同时启用时先调整人数、再混编，例如原本20人，2倍后40人，30%混编为12名原神兵＋28名原版土匪。

## 角色、装备与属性

只有**云堇、刻晴、凝光**为近战骑兵。妮露、闲云、薇斯纳为骑射兵；诺艾尔、琴为盾步兵，神里绫华两套为双手突击兵。每个角色有独立固定装备套；完整物品、坐骑、防具等效重量与数值基准见 [兵种配置](docs/troops.md)。

所有新增兵种五个防具槽为空，保留原角色外观。固有护甲按“兵种ID＋种族ID”匹配，使用现有 RaceTroopBuilder 的共享护甲协议和相同运行 DLL；不声明种族全局默认值，不改变同种族民兵。兵种覆盖替代种族固有值，实际装备护甲独立相加，原版特长随后计算。其他模组若对同一兵种重复声明护甲，组件会报错；额外全局修改护甲的外部代码仍需兼容验证。

等效负重在原版防具重量计算后、原版负重特长修正前加入；武器、盾牌、弹药及马具重量保持真实计算，不重复加重。负重按新增兵种与种族匹配，招募后仍生效；其他兵种不变。角色体型、骨架和动作仍可能影响实测跑速，不保证相同重量必然完全同速。

熟练度完整复制对应原版 T5；兵种本身为 T3，没有升级分支，可按原版机制成为俘虏、招募。原版自动战斗、工资和经验机制继续按本兵种身份处理，固有护甲不自动将模拟战力提高为 T5。人物模型、原有布料与界面兼容边界继承原神合集的验收范围。

## 安装与设置

依赖现有 Harmony、ButterLib、UIExtenderEx、MCM v5 与 **Genshin Race Collection**。故事战役同时启用原版 StoryMode，沙盒不强制依赖 StoryMode。本机已按创意工坊 MCM v5.12.3 构建，使用已安装的前置，不再打包另一份 Harmony／MCM。Mod ZIP 解压到游戏 `Modules/`；启动器放在前置、原版模块、原神合集之后，启用 **Genshin Bandit Race**。

进入战役后，在 MCM 的“原神土匪混编 / Genshin Bandit Race”中设置，按存档保存。保存后影响后续新队伍与战斗属性更新；修改负重后已经在场的角色依赖下一次原版属性刷新。

## 停用与卸载准备

关闭“启用新队伍混编”只停止新增，保留已有兵种；继续保留本模块和原神合集，是继续使用当前存档的保守方式。只删除数量调节 Mod 不影响本模块兵种定义。

**不能保证完整删除本模块后当前存档可用。**新增兵种可能进入玩家／AI队伍、驻军、俘虏及其他存档引用。请保留安装前存档作为可靠回退。

MCM“清理本Mod兵种”需要返回大地图并确认：关闭混编，把当前可枚举队伍、聚落驻军与俘虏中的本Mod兵转换为原版劫匪，保留人数、伤员和经验。请先备份，清理后另存新档并重载验证。此功能不保证清除任务、历史等所有引用，不等于卸载安全认证；存在相关进行中战斗时不执行。若其他民兵 Mod 仍使用原神种族，原神合集必须继续保留。

## 工程、构建与检查

`tools/generate_data.py` 从当前原版 XML 生成22套独立装备、T5技能／护甲／重量、六类完整覆盖清单，写入自己的模块；`source/Runtime/` 为运行源码，`source/Tests/` 为离线检查，`reports/` 为报告，`dist/` 保留安装包及源码包。

在工作区根运行：

```powershell
python mods/GenshinBanditRace/tools/release.py --install
```

依赖 .NET Framework 4.7.2 开发环境、.NET SDK、Python、游戏 DLL、已安装前置，以及工作区 RaceTroopBuilder 已构建的共享护甲 DLL。源码包包含该 DLL 与护甲源码快照；单独解压后在本目录运行 `python tools/release.py --install`，默认从已安装原神合集读取种族定义。安装先验证工作区原神合集源工程与已安装资源一致，只备份和更新本模块；不写入原神合集、Native、前置或存档。已安装 Bandit Population Tuning 时执行组合顺序检查，否则明确记录跳过，不影响独立构建。

离线检查覆盖沙盒 `Campaign`／故事 `CampaignStoryMode` 两种XML选择、22个完整兵种引用（含 `gbr_noelle`）、故事运行类型的绑定分支、22套装备唯一性、T3身份、三名骑兵名单、六类完整覆盖、各类完整22兵种池、配额与总人数守恒、MCM参数、兵种护甲隔离、真实 DLL 护甲／负重／生成入口挂接及两模块执行顺序。详见 检查输出（见源码包 `reports/offline_tests.txt`）、配置报告（见源码包 `reports/troop_configuration.json`）、发布报告（见源码包 `reports/release_validation.json`）。故事模式跳过教程／读档、游戏内菜单、实际生成、战场外观／负重、俘虏招募、清理与保存读档待用户实测；助手不启动游戏。
