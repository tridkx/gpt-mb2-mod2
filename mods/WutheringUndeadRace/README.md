# Wuthering Undead Race

鸣潮感染危机 `v0.1.1`，适配本机骑砍2 Native `v1.4.8` 的单人战役与故事模式。新增40个感染兵、8名感染统领、陆地尸群生成、战败转化、尸潮军团和清剿奖励。复用 **Wuthering Waves Race Collection v0.1.1** 的模型、骨架与布料，不修改合集或原版文件。

## 安装与快速开始

本机安装目录为 `D:/SteamLibrary/steamapps/common/Mount & Blade II Bannerlord/Modules/WutheringUndeadRace/`。安装包见 [Mod ZIP](dist/WutheringUndeadRace_v0.1.1_Mod.zip)，源码见 [Source ZIP](dist/WutheringUndeadRace_v0.1.1_Source.zip)。

启动器按以下顺序启用：现有 Harmony → ButterLib → UIExtenderEx → MCM v5 → 原版单机模块 → **Wuthering Waves Race Collection** → **Wuthering Undead Race**。不额外打包前置，助手不启动游戏。进入战役后，在 MCM 的“鸣潮感染危机 / Wuthering Undead Race”调整设置，设置按存档保存。

默认从本模块首次进入该存档时开始计时，经过3天宽限后生成。旧档也可初始化，但新增英雄、势力与兵种会进入存档，使用独立测试存档并保留启用前备份。关闭“允许生成与领主重生”只停止新增，已有尸群继续活动；关闭“允许尸群军团”后，空闲军团在后续小时检查中解散。没有已验证的安全卸载功能，直接移除模块或鸣潮合集可能导致相关存档无法加载。

## 兵种与领主

| 职业 | 角色 | 区分 |
| --- | --- | --- |
| 步兵 | 鉴心／长离 | 盾锤铁壁／双手狂战 |
| 射手 | 折枝／吟霖 | 长弓狙击／重弩处决 |
| 骑兵 | 今汐／今汐·桃夭灼灼 | 枪盾重骑／长柄挥砍 |
| 骑射 | 白芷／守岸人 | 轻装快射／重装火力 |

每个种族只有一个职业、T1—T5五阶，内部 Level 为6／11／16／21／26。同角色职业线逐阶升级，模型保持原貌。头、身、披风、手套、腿甲槽为空，使用独立运行组件提供固有护甲和防具等效负重。武器、盾牌、弹药、马匹及马具为真实物品，其重量照常计算。独立感染武器复用原版外观，按职业选择组合；高阶和统领的弓弩、弹药、盾牌数值强化，锻造近战武器使用可见的设计尺寸变化，技能另有强化。武器和护甲不写回原版兵种。

守岸人所有兵阶都保留近战钝器，T5单手技能90、弓术240。完整护甲、重量、武器基准见 [兵种数据](docs/troops.md)，技能、物品ID与坐骑见 [配置明细](reports/troop_configuration.json)。

八名统领在战役就绪后由角色模板创建为原生英雄，每角色一名；模板仅声明is_template，使用独立种族变体；skin缩放参数为原种族的1.5倍，引用同一模型与骨架。统领护甲为本角色T5固有护甲的1.6倍，使用强化武器与技能。普通感染兵保持原尺寸。统领战败逃脱，默认3天后重新带队，仍受队伍数和全局兵力上限约束；同一领主不会重复存在多支队伍。正常领主被尸群击败也会逃脱，不转化为感染领主；玩家被俘时在战斗结束后的地图检查中释放。

## 生成、行为与军团

感染者拥有独立家族和王国，与其他非中立势力保持战争；后续出现的王国、独立家族和土匪势力会在小时检查中补齐敌对。王国不取得聚落所有权。尸群不会互相攻击，不消耗粮食或工资，地图士气固定100，不接受正常外交停战。玩家遭遇直接进入战斗菜单，不经过过路费、招募或谈判对话。

陆地尸群在随机城镇周边可通行、要求路径连通的位置生成，避开玩家极近位置。空闲尸群搜索半径内的非感染普通野外部队并追击，不按敌我强弱逃跑；无目标时巡逻。任务专用队、驻军、民兵、聚落与海上目标不主动追击。所有移动指令使用陆地导航，不开放攻城、劫村或聚落感染。

八名统领各自带队，附近至少两支领主尸群可形成真正的原生军团，各队保留兵员和身份。**游荡的无英雄尸群保持独立行动**，不加入军团。成员实际行军靠拢后附属于领队，不瞬移集合；加入费用为零，凝聚力由感染逻辑维持，不消耗影响力。军团默认最多4队、600名普通兵，持续48小时，集结冷却24小时；战斗中延后解散。领队被消灭时沿用原生解散机制。

大地图速度默认为正常计算结果的 **1.05倍**，只在最终速度处应用一次。保留地形、人数与步骑构成的原版差异；可选最终速度上限默认为0，即不限制。战场跑动和骑乘继续由兵种技能、负重与坐骑决定。

## 转化、成长与清剿奖励

尸群获胜后，可分别开启“阵亡者参与转化”和“实际被俘者参与转化”，默认均开启，转化率100%。俘虏增量在原版释放旧俘虏之后、实际俘获败兵前后取样；逃脱者、英雄和战前已有俘虏不进入转化人数。按原职业与兵阶映射，最高T5，再从该职业两名角色中等概率选择。

转化兵加入参战胜方尸群，优先补充人数较少且仍有容量的队伍。单队、全局或军团容量耗尽后舍弃超额转化，不拆分新队。未转化的普通俘虏不长期留在尸群。兵力上限只计算尸群普通成员，不包括8名英雄，也不包括玩家／正常AI队伍中获得的感染兵。降低全局或单队上限不会直接删除已有成员，只限制后续增加；军团超出其新上限时在空闲小时检查中解散。

尸群积累原版战斗经验后自动升级，不消耗金币、马匹或战马。默认经验需求倍率1，只升级健康成员、每次检查最多向上升一阶；受伤者保留原兵阶与经验。正常部队拥有感染兵时继续按原版付费升级。自动结算战力倍率默认1，可在MCM调节；场景武器与固有护甲不会逐项进入原版模拟公式。

玩家和正常AI领主获胜均可获得额外奖励，按**实际阵亡的普通感染兵**计算，伤员、俘虏、逃兵与统领不计入：

- 每个兵阶10金币，例如消灭一名T5奖励50金币。
- 每个兵阶0.05影响力，例如消灭一名T5奖励0.25影响力。直接记入胜方领主家族，包括尚未建国的玩家家族。
- 感染兵奖励默认10%，保留被消灭者的兵种与兵阶。各兵种不足一人的小数部分按概率取整。

联合战斗按各胜方领主队伍的战斗贡献分配，同一场奖励总额不重复发放。奖励兵走原版战后救援成员入口，玩家可在战后界面接收；普通队伍容量仍受原版限制。奖励兵保留战斗装备、固有护甲和等效负重，但不会把正常队伍变为尸群，也不获得尸群转化、免费升级或地图加速机制。

## 默认设置

| 设置 | 默认 |
| --- | ---: |
| 宽限期／生成间隔 | 3天／12小时 |
| 队伍数／普通兵总数／单队上限 | 24／3000／250 |
| 新队人数／最高初始兵阶 | 20—45／T3 |
| 领主重生冷却 | 3天 |
| 地图速度倍率／追击半径 | 1.05／25地图单位 |
| 军团集结半径／最多队数／普通兵上限 | 35地图单位／4／600 |
| 军团持续／集结冷却 | 48小时／24小时 |

以上参数与升级经验需求、模拟战力等均可通过MCM调整。全局上限与领主重生冲突时，领主等待空缺；宽限期内不初始化感染势力或生成队伍。

## 开发与检查

`source/Runtime/` 为运行源码，`source/Tests/` 为离线检查，`tools/generate_data.py` 从本机原版数据生成本模块，`module/WutheringUndeadRace/` 为安装内容。`build/` 保存本机接口回读和缓存，不进入源码包；`dist/` 保留交付包。依赖 .NET Framework 4.7.2 引用程序集、.NET SDK、Python、本机游戏DLL与现有MCM／Harmony。

在工作区根运行：

```powershell
& 'C:/ProgramData/anaconda3/python.exe' -X utf8 mods/WutheringUndeadRace/tools/release.py --install
```

省略 `--install` 只生成、构建、检查和打包。安装检查鸣潮合集工程与游戏安装的逐文件哈希一致，只备份和写入本模块，不修改存档、前置或依赖模块。源码包放回同级 `mods/` 布局后重建；本机路径配置见 `source/GameReferences.props` 和 `tools/release.py`。

[离线检查](reports/offline_tests.txt)覆盖实际游戏XML Schema、40兵种分组与升级引用、守岸人副武器、名额与联合奖励守恒、真实Roster操作、行为状态保存读回，以及当前游戏实际方法的Harmony补丁编译。[发布检查](reports/release_validation.json)记录安装与包文件哈希。

## 当前限制与游戏验收

此版本为游戏验收版本。离线通过不代表已进入游戏验证；助手未启动游戏。需要用户确认：新档／旧档加载、MCM、实际生成追击、亲自战斗与AI自动结算、转化人数、清剿奖励、免费升级、军团集合／解散、统领战败3天重生及保存读档。

1.5倍领主的战场实际尺寸、碰撞和骑乘比例尚待实测，XML倍率不是实机尺寸测量。新种族变体没有另制马匹尺寸；大型骑手与原马的比例、握持及骑乘可能需回调。人物预览、动作和布料继承鸣潮合集已有验收边界，新增领主变体的百科／队伍／物品栏预览也需单独检查。没有增加或修改TPAC布料数据，复用依赖的布料资源和诊断。

其他修改战役AI、战争／军团、兵种、速度、护甲或战斗结算的Mod需组合测试。补丁签名不匹配时撤回本模块补丁并提示，角色反序列化状态、完整缺失名单与故障详情写入安装目录 `ModuleData/runtime.log`；初始化失败会撤回本模块全部补丁。游戏升级后应重新核对接口与原版数据。
