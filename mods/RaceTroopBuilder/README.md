# Race Troop Builder

Windows 自定义种族兵种树拼装器 v0.2.0，适用于本机 Bannerlord v1.4.8。人类用户使用桌面 GUI，AI 使用 JSON 工程与 CLI，两者共用 C# 核心。

每个兵种固定一个种族，不同节点可使用不同种族。生成的 Mod 保留原版兵种 ID、招募引用、文化、等级、技能与升级关系，按配置替换种族和装备。种族模型、TPAC、skins、Monster、动作与 UI 适配由外部依赖 Mod 提供，输出包不包含这些资源。

## 快速开始

本工作区双击 `Launch-GUI.cmd`。发布包解压后同样双击包内 `Launch-GUI.cmd`；包内带 Windows x64 .NET 运行时，无需单独安装 SDK。

1. 检查游戏目录与 Mod 来源目录，点击“扫描 / 刷新目录”。默认从当前工作区 `mods/` 读取，支持系列嵌套、独立工程、已安装模块及自选目录，每行一个来源。
2. 在兵种树中选择节点，选择种族、性别和脸参数。完整固定角色通常选择“固定参数”及“清除防具”；可变脸种族通常保留原版参数。
3. 选择“沿用种族固有护甲”或“覆盖种族固有护甲”。覆盖模式填写头、身、臂、腿四项；种族未声明默认值时会明确提示。顶部语言菜单可切换兵种和物品的中英名称，搜索支持两种语言及 ID。
4. 选择单节点、全部升级分支或当前文化所有普通士兵，点击“应用配置到所选范围”。文化范围也包含该文化的民兵、守卫、雇佣及任务士兵；只改正常招募树时使用升级分支。
5. 修改装备时勾选“覆盖战斗装备”，编辑各槽、复制或删除装备套，再点击应用。未勾选时各兵种保留自身武器；清除防具同时处理战斗与平民套。
6. 保存 JSON 工程，查看检查及修改对比，导出 Mod / ZIP。安装好匹配的种族依赖后，可以使用“安装最近构建”。工具不启动游戏。

示例 [帝国普通树 → 月清疏](examples/empire-yueqingshu.json) 覆盖 `imperial_recruit` 的全部升级分支（本机 14 个节点），不覆盖贵族线。示例只供打开、检查和导出，不在工具启动时自动安装或修改游戏。

## AI 接口

发布包中的 `rtb.cmd` 或 `app/cli/RaceTroopBuilder.Cli.exe` 提供 `scan`、`catalog`、`troop`、`new`、`configure`、`validate`、`preview`、`build`、`package`、`install` 命令。标准输出为 JSON；退出码 0 成功、2 配置检查失败、1 操作失败。使用 [接口与工程格式](docs/interface.md) 和 [JSON Schema](schemas/project.schema.json) 拼装工程。

CLI 直接写出的工程可在 GUI 中打开。GUI 修改配置时会将选择范围更新为明确的兵种 ID，并解除已有规则的目标重叠。GUI 的 JSON 页是只读检查视图；CLI/JSON 支持平民套和自定义显示名，GUI 主要编辑战斗套。

## 加载与装备行为

启动器从上到下：原版依赖 → 种族依赖 Mod → 生成的兵种替换 Mod。输出模块自动声明所有必需依赖。缺少种族、皮肤性别、必需 DLL 或发生依赖循环时，检查阻止导出；安装时还校验依赖版本与资源哈希。

`Item0～Item3` 是四个武器槽，原版出生路径从候选套随机取槽位，并不保证整套装备一起选中。例如 Item0 候选为单手1/单手2，Item1 候选为双手1/双手2，可能出现单手1+双手2，但不会把两把仅位于 Item0 的单手武器一起发给士兵。工具沿用该机制，并提示弓箭、弩矢、投石索弹药及坐骑的随机组合问题。

## 固有护甲

外部种族作者通过 `ModuleData/rtb_race_armor.xml` 声明种族默认值；替换器默认继承，可按兵种覆盖。无防具也生效，兵种覆盖替换种族固有值，不重复相加；实际穿戴防具的护甲仍独立相加，原版特长随后生效。种族默认文件不复制到生成包中。

有协议默认值或兵种覆盖时，生成模块自动携带自己的 .NET Framework 4.7.2 护甲组件和 Harmony 2.4.2，不需要另外安装 Harmony 模组。只有种族默认值、没有兵种替换时，种族作者可使用发布包内的 `runtime-provider/RaceTroopArmor` 通用模块作为运行入口。工具不会修改外部种族模块。协议、接入方式和边界统一见 [固有护甲接口](docs/armor.md)。

## 项目结构与开发

```text
source/Core/       发现、配置、校验、XSLT、打包与安装
source/Cli/        AI 命令行入口
source/Gui/        Windows WPF 编辑器
source/Tests/      合成模块与本机集成检查
source/Runtime/    游戏内固有护甲组件（net472）
source/RuntimeTests/ 游戏 DLL 补丁离线检查
source/Shared/     桌面与游戏共享护甲协议
schemas/           工程格式
examples/          可复用示例配置
tools/             构建与发布脚本
build/             检查、预览及导出缓存
dist/              带运行时的桌面工具与历史交付包
reports/           离线验证记录
```

源代码需要 Windows、.NET 10 SDK、.NET Framework 4.7.2 引用程序集及本机 v1.4.8 游戏 DLL。游戏 DLL 只作为编译引用，不进入发布包。运行 `powershell -File tools/build.ps1 -LocalGameChecks` 完成编译、配置与护甲检查、本机全部士兵转换、发布 GUI/CLI 和打包；不启动游戏、不安装示例。源码编译入口为 `source/RaceTroopBuilder.slnx`。详情见 [验证与游戏验收](docs/validation.md)，版本变更见 [CHANGELOG](CHANGELOG.md)。

当前离线结果见 [发布验证报告](reports/release_validation.json) 和 [GUI 预览](reports/gui_preview.png)。

## 当前限制

- 只适配并离线验证 v1.4.8；其他版本拒绝生成，需先更新接口与数据检查。
- 不支持同一兵种混合种族、严格整套装备随机、调整升级边或新增招募入口；本项目替换现有树。
- GUI 展示兵种树、配置和 XML 对比，没有游戏模型 3D 渲染。装备编辑的工作草稿须点击“应用配置”后才进入工程和导出。
- 语言切换覆盖兵种和物品名称；GUI 操作标签仍为中文。缺少原版中文翻译时回退英文。
- 装备目录仅收录原版已注册物品；尚不支持纯 `battleTemplate/civilianTemplate` 隐式继承且没有 `Equipments` 的士兵定义。
- 从原版数据建立目标节点。依赖或其他 Mod 对同一目标的修改会被本工具的完整节点替换覆盖；后加载的其他 Mod 仍可能再次覆盖。未编辑节点继续沿用其他 Mod 的处理。
- 护甲组件适配原版战役的 Sandbox 属性计算；替换整个计算模型或另行硬编码护甲的 Mod 需要兼容适配。自动战斗仍按原版规则，不额外根据固有护甲提高战力。
- 离线检查不验证 TPAC 内部模型、动画与游戏实际渲染，种族依赖需是可用模块。实机招募、战斗与预览验收由用户完成。

## 注意事项

**重复模块 ID：** 同一个种族模块同时出现在工程与游戏目录时会产生来源歧义。将来源目录缩小为唯一模块，或使用与安装内容相同的来源。无关装备合集的重复工程只显示提示。

**安装依赖不匹配：** 源工程与已安装种族的版本或文件哈希不一致时，安装会停止。先安装匹配版本的依赖，或改为扫描游戏中已经安装的种族模块，再重新导出。工具不会代替用户复制或修复种族依赖。

**目标目录占用：** 安装仅允许更新带本工具标记的同 ID 模块。旧版先完整 ZIP 备份，再进行暂存校验与目录切换；资源占用导致失败时保留旧模块。退出游戏后重试，不强制结束游戏进程。
