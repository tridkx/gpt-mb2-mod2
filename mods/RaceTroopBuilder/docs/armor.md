# 种族固有护甲接口

适用：RaceTroopBuilder v0.2.0、本机 Bannerlord v1.4.8 的原版单人战役。此功能不依赖防具物品或种族网格，不修改自动战斗模型。

## 数据归属与计算

种族 Mod 提供头、身、臂、腿四项默认固有护甲。兵种规则省略 `armor` 或使用 `mode: inherit` 时沿用种族默认；`mode: override` 用该兵种的四项数值替换种族固有值。每项为 0～500 整数，零值是真正覆盖为零。

计算顺序为：实际防具护甲＋选中的固有护甲，然后原版特长继续计算。无防具时仍具有固有护甲。覆盖不会同时累加种族默认值；实际防具未被自动删除，需要无装备外观时另选 `stripArmor`。

## 种族作者接入

在自己的模块 `ModuleData/rtb_race_armor.xml` 声明：

```xml
<RaceArmor schemaVersion="1">
  <Race id="your_registered_race" head="20" body="40" arms="25" legs="30" />
</RaceArmor>
```

示例数字仅说明格式。ID 必须是该模块已注册的种族，不是模块 ID；一个文件可包含多个种族。四项必须齐全，重复 ID、错误版本和非法值会报错。这个文件是运行组件主动读取的协议数据，不要注册为游戏 Items、NPCCharacters 或 skins。

种族默认值始终留在依赖 Mod。生成的兵种模块不复制默认文件，只保存明确的兵种覆盖；安装时校验依赖默认文件的哈希。无协议的种族显示“未声明”，沿用模式不干预其已有护甲实现，也不把未知值伪装为已知的零。

种族默认数据需要运行入口。使用本工具生成兵种模块时会自动附带入口；若种族独立使用，安装发布包的 `runtime-provider/RaceTroopArmor` 并启用，顺序为原版模块 → 种族模块 → RaceTroopArmor。种族作者可将 RaceTroopArmor 作为必需依赖，或把其两个 DLL 和 `<SubModule>` 条目集成到自己的种族模块；两种入口使用同一注册器，多个入口不会重复安装补丁。不必两种入口都安装。

默认值作用于该种族的所有人形角色，包括未被替换器选择的兵种与英雄。兵种覆盖只作用于匹配兵种 ID 且仍使用指定种族的角色。只有启用的模块会贡献数据。多个模块声明相同种族默认值、或对同一兵种重复提供覆盖时明确报错，避免加载顺序造成隐式叠加。

## AI / JSON 配置

沿用默认值，可省略 `armor` 或写：

```json
"armor": { "mode": "inherit" }
```

按兵种覆盖：

```json
"armor": { "mode": "override", "head": 20, "body": 40, "arms": 25, "legs": 30 }
```

覆盖必须明确填写四项；沿用模式不接受非零覆盖字段。`preview` 同时返回种族默认和兵种覆盖，原版兵种 XML 本身不增加虚构的护甲属性。GUI 的覆盖工作草稿须点击“应用配置”后才进入工程。

## 运行与兼容边界

组件使用 net472、Harmony 2.4.2，接入 `SandboxAgentStatCalculateModel.UpdateHumanStats` 四个装备护甲汇总入口。每次更新只将当前固有值加入新的装备汇总结果，随后原版特长执行；不会基于上一轮的结果继续累加。游戏 API 变动导致入口签名或数量不符合预期时明确失败。

这些数值提供护甲减伤，不增加装备负重、装备价值或盔甲材质。头部数值对应原版头／颈，身体对应胸／腹／肩，左右臂、双腿按原版划分。场景战斗与自动战斗是不同模型，本功能不按固有护甲额外提高模拟战力。

如果某个种族 Mod 已经用独立 DLL 硬编码护甲，它必须接入这份协议或提供兼容适配；替换器不能可靠猜测或消除任意 Mod 的加成。替换整个战斗计算模型、额外修改最终护甲或使用不同 Harmony 版本的模块须做兼容验收。仅加载顺序不能保证覆盖任意第三方代码。

离线检查包括默认／覆盖／零值、原版人类不受影响、注册器重置、冲突拒绝及真实 v1.4.8 方法的补丁编译。游戏验收仍需检查空防具士兵、招募和升级、骑乘／徒步及特长变化后的护甲和受伤效果。
