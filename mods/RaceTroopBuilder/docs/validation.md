# 验证与验收

## 离线检查

`source/Tests` 使用独立合成游戏和种族模块，验证递归目录识别、注册入口、相对路径、根节点遍历、未知兵种/种族、缺失性别、规则重叠、升级及依赖循环、来源重复、装备集合展开、全部防具清除、随机弹药提示、保留本地化花括号与注释、原版目录保护、输出哈希、交付包边界、依赖一致性、旧版备份及文件占用失败后的数据保留。

```powershell
dotnet run --project source/Tests/RaceTroopBuilder.Tests.csproj -- build/tests --local-game
powershell -File tools/build.ps1 -LocalGameChecks
```

`--local-game` 读取当前工作区和安装游戏，对全部可编辑普通士兵配置固定月清疏种族，并在独立缓存中实际生成转换。这只是离线覆盖检查，不安装该全量测试模块。

构建阶段编译 XSLT，并对原版及所选依赖已注册的 NPCCharacters XML 逐个应用转换。目标节点必须与预期完整定义一致，无关节点的属性、有效文本、子节点和注释须不变；只忽略排版空白及等价空标签形式。工具不模拟整个游戏的 XSD 合并器，也不声称替代运行时检查。

GUI 的 `--smoke-test PNG_PATH` 在离屏窗口中实际扫描、选择帝国新兵、应用完整分支、编辑武器槽、复制套、更新重叠规则、搜索并生成 PNG。它不安装游戏 Mod。测试入口用于开发，不需要正常用户调用。

## 交付和安装

发布脚本编译 Release、执行检查、发布带 Windows x64 运行时的 GUI 与 CLI，并创建带时间戳的工具 ZIP，保留历史 ZIP。桌面工具发布包与用户导出的游戏 Mod 是两个独立交付物。

游戏 Mod 安装前重新核对构建文件哈希、原版版本、全部依赖版本和自定义依赖资源哈希。只有带 RaceTroopBuilder 标记的同 ID 模块可更新。安装流程先保留旧目录 ZIP，再复制并校验暂存目录，最后切换自己的模块；失败时恢复旧目录。禁止安装覆盖 Native 等原版模块。不会复制依赖资源、开启游戏或修改启动器设置。

## 用户游戏验收

1. 按报告顺序启用依赖种族和生成模块，确认启动器无缺失依赖。
2. 查看目标新兵及所有升级节点的百科和队伍预览，确认种族、性别、武器与身体可见。
3. 招募并升级，检查各分支仍可达，节点没有意外恢复为原版种族。
4. 验证野战、增援和相关骑乘/远程动作，检查握持、弹药、身体遮盖、骨架与动画。
5. 查看未涉及的兵种，确认其原有行为；存在其他兵种覆盖 Mod 时按实际加载集合回归。
6. 新存档先测试；已有存档单独验收，不从离线 XML 推断存档完全兼容。

运行测试由用户完成；报告应分别记录离线通过和用户实际验收范围。依赖种族自身的捏脸、预览重建和战斗骨架问题由依赖工程处理。
