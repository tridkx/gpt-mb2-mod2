# 无界面布料数据生成记录

本机游戏 Native 版本 v1.4.8。只读取原生资源，未修改 Native、未启动游戏或编辑器。

官方 [布料教程](https://moddocs.bannerlord.com/editor/resource-editors/cloth_simulation/) 说明约束预处理与映射数据的用途、代理参数覆盖规则；本次具体 TPAC 二进制布局来自本机原生资源对照，而非官方公布的格式规范。

## 样本和数据类型

- `meshes_shared_3.tpac` 的 `clo_battania_dress_c`、`clo_khuzait_civil_coat` 都包含类型 GUID `b97e0f10-df49-4666-8f1d-ada6630d4b4e`，对应模拟预处理数据。
- `battania_armor.tpac` 的 `battania_dress_c` 引用上述独立代理，其启用模拟的两个 LOD0 子网格含类型 `af41613e-bd4d-46ec-8284-debb56c042dc`，对应映射。
- 天香 v1.4.1 没有这两类段。不能只凭缺少段证明游戏不会自行生成，但前几版检查没有覆盖它们；现已把实际所需的数据直接打包。

## 已验证的布局

约束段头部为 float 距离量化系数、五个 uint 计数（约束、粒子、固定粒子、非活动三角形使用粒子、碰撞索引），以及两组 vec4 包围盒。后接长度、粒子对、约束批次、碰撞三角形批次、压缩位置、压缩法线、渲染顶点到粒子的重排、碰撞三角形、活动距离、逆质量、骨索引、浮点权重、锚定距离与粒子索引数组。

压缩位置使用每轴 21 位、固定 [-100,100] 坐标范围，两个 uint 顺序与通常的 uint64 字节顺序不同；最低位在样本中为零。不得直接把编辑顶点编号用于映射，必须经过预处理重排。映射段是每个外观顶点的三个 ushort 粒子索引和四个 float；前三个为和为 1 的重心权重，第四个是沿插值法线的偏移。原生平滑法线重建存在压缩误差，天香 LOD0 使用重合顶点的精确一热映射，LOD1 使用相同法线基求解。

两件原生约束段均完整解析并逐字节回写一致。根据重排表恢复粒子后，全部约束长度与实际几何误差分别不超过 8.67e-8 和 5.94e-8 米；压缩位置误差分别不超过 0.000153 和 0.000146 米。

新生成器使用三角网格边上的拉伸约束和相邻三角形对边顶点的距离弯曲约束，没有额外剪切或缝合约束；每批避免共享粒子写入。碰撞三角形同样分批。固定点先排列，骨索引与权重按同一重排变换。活动距离在段内以浮点保存，裙摆精确保留原值；代理源的 byte Alpha 对应可编辑近似。

写入后通过 TPAC 实际数据段回读、原始字节一致、完整元数据校验和、引用检查、映射重建、源文件与保留资源检查。具体版本与包摘要见 `mapped_sleeves_validation.json`。

## 实际限制

这是依据本机格式实现的离线生成器，尚未在官方引擎中验证所有数据的运行语义。没有调用官方求解器，不能保证抬臂、骑乘碰撞或低画质的模拟开关行为。新文件也不是原生编辑器 cooking 的逐字节复刻：采用上述明确约束生成规则。安装保留 v1.4.1 回退包，由用户在游戏内测试；后续游戏版本改变格式时须重新核对样本。

桌面工具故障无需由用户手工操作 GUI 绕过。本次写入、打包、安装与本地 Git 工作均由代理完成。
